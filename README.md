# llm-cost-cli

Сквозной проект обучения: читает логи вызовов LLM и считает деньги.

**Стенд подготовлен 17.09.2026** (наставник). Задача 1 — твоя.

## Данные

`data/llm_log.csv` — логи вызовов за 30 дней: **2000 строк данных**, 5 моделей.

| Поле | Что это |
|---|---|
| `ts` | дата и время вызова, `2026-09-17 21:26:39` |
| `model` | имя модели |
| `tokens_in` | входные токены |
| `tokens_out` | выходные токены |
| `cost_usd` | стоимость вызова в долларах |

**В файле намеренно есть битые строки и мусор.** Файл готовить не надо — надо, чтобы скрипт их пережил.

## Задание 1 — `report.py`

Обязательная часть:

1. Прочитать `data/llm_log.csv`.
2. Посчитать по каждой модели: количество вызовов, сумму `tokens_in`, сумму `tokens_out`, суммарную стоимость.
3. Напечатать таблицу, отсортированную по стоимости по убыванию: модель, вызовы, токены, деньги.
4. В конце вывести итоги: сколько строк данных прочитано, **сколько строк пропущено как битые**, общая сумма в долларах.
5. Скрипт **не должен падать** ни на одной строке. Про каждую пропущенную — предупреждение (например, `пропущено: строка 195, tokens_in = 'N/A'`), максимум 10 примеров в выводе.
6. Функции: разбор одной строки отдельно (`parse_line`), агрегация отдельно, печать отчёта отдельно. Всё в файле `report.py`, запуск без аргументов.

Бонус (по желанию, если останутся силы): часть битых строк не пропускать, а **восстанавливать** — например, лишние пробелы в дате и заглавные буквы в имени модели (`GPT-4o` → `gpt-4o`). Тогда в отчёте укажи, сколько строк восстановлено и сколько реально выброшено.

## Критерий «готово»

- `python3 report.py` печатает таблицу по всем 5 моделям и итоги;
- порядок — по стоимости по убыванию;
- ни одного падения и ни одного трейсбека;
- список пропущенных строк объяснён: видно, какие виды дефектов встретились.

## Подсказки (не готовый код)

- Читать файл построчно (`for line in f`), а не целиком в память.
- Разделить строку: `line.split(",")`, а не `csv` — сначала попробуй так, поймёшь, где csv удобнее.
- Проверка «строка годная» — это `try/except` вокруг приведения типов плюс `if not model`.
- Агрегация — словарь: `{model: {...}}`. Сортировка — `sorted(agg.items(), key=lambda kv: kv[1]["cost"], reverse=True)`.
- Печать — f-строки с выравниванием: `f"{model:<20}{calls:>7}"`.
- Имя файла с данными — относительный путь `data/llm_log.csv`; запускать из корня проекта.

## Как сдаём

Прислать код в чат наставнику. Наставник запускает его на настоящем файле, показывает реальный вывод и разбирает, где ошибка. Потом — коммит: `git add -A && git commit -m "report: отчёт по моделям"`.
